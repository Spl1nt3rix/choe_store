# Shoe Store — готовый учебный проект

Приложение на Python + PyQt6 + PostgreSQL для модулей 2–4: авторизация, роли, список товаров, поиск/сортировка/фильтр для менеджера и администратора, CRUD товаров только у администратора, просмотр заказов у менеджера/администратора и CRUD заказов только у администратора.

## 1. Подготовка PostgreSQL

1. В pgAdmin создайте базу `shoe_store`.
2. Откройте для неё **Query Tool**, откройте `init_db.sql` из корня проекта и выполните скрипт (F5). Он рассчитан на пустую базу.
3. Если у вас уже есть база и таблицы из модуля 1, **не выполняйте `init_db.sql` повторно**. Проверьте структуру; для добавления артикула заказа выполните `migration_module4.sql` один раз.

## 2. Установка и пароль подключения

Из корня проекта откройте терминал:

```bash
python -m venv venv
source venv/bin/activate       # Fedora/Linux
python -m pip install -r requirements.txt
```

В `db.py` замените `CHANGE_ME` на пароль пользователя PostgreSQL, которым подключаетесь в pgAdmin. Альтернатива — задать переменную окружения `SHOESTORE_PASSWORD`.

На Windows активируйте окружение командой `venv\\Scripts\\activate`.

## 3. Настройка тестовых паролей

В активированном окружении выполните:

```bash
python set_test_passwords.py
```

Для демонстрационных учётных записей будет установлен пароль `Demo123!`:

| Роль | Логин | Пароль |
|---|---|---|
| Клиент | `client` | `Demo123!` |
| Клиент | `petrova` | `Demo123!` |
| Менеджер | `manager` | `Demo123!` |
| Администратор | `admin` | `Demo123!` |

Это учебные тестовые пароли. Перед реальным использованием замените их.

## 4. Запуск

```bash
python main.py
```

Если открыть как гость — доступны только товары без поиска и управления. Клиент также видит товары. Менеджер получает поиск/фильтрацию/сортировку и просмотр заказов. Администратор может создавать, изменять и удалять товары и заказы.

## 5. Сборка исполняемого файла

Linux:

```bash
pyinstaller --noconfirm --clean --noconsole --onefile --name ShoeStore --add-data "styles.qss:." main.py
```

Windows:

```powershell
pyinstaller --noconfirm --clean --noconsole --onefile --name ShoeStore --add-data "styles.qss;." main.py
```

Файл появится в `dist/`. Приложение всё равно требует работающий PostgreSQL и правильные параметры подключения.

## 6. Перед сдачей

- Проверьте вход под всеми ролями.
- Проверьте добавление/редактирование товара под администратором и отсутствие этих кнопок у остальных.
- Проверьте, что менеджер видит раздел заказов, но не может менять данные.
- Проверьте уникальность артикула и необязательную дату выдачи.
- В pgAdmin сделайте Backup базы в формате **Plain**, включив схему и данные.
- Добавьте в репозиторий исходники папками и файлами, SQL-дамп, ER-диаграмму, блок-схему и стайл-гайд.

## Примечания

- Код проверен статически на синтаксис в среде сборки, но не запускался против вашей локальной PostgreSQL. Поэтому после распаковки обязательно проверьте подключение и схему.
- Для существующей БД убедитесь, что названия столбцов соответствуют `init_db.sql` и методичке модуля 1: особенно `role_name`, `category_name`, `manufacturer_name`, `supplier_name`, `status_name`.
